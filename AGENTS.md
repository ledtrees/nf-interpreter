# nf-interpreter — LEDTREES

Нативная прошивка LEDTREES: форк .NET nanoFramework, nanoCLR для ESP32-S3. Managed-код и инструменты — ledtrees-esp32; компоненты ESP-IDF — ledtrees-idf-components.

## Общие правила для всех ИИ-агентов

- На русские запросы отвечать по-русски. API, технические термины и идентификаторы оставлять на английском.
- Новые комментарии в коде писать на английском; очевидное не комментировать. Следовать стилю проекта.
- Не выполнять commit и push без явной просьбы. Сообщения коммитов — на английском, без `Co-Authored-By`.
- Перед изменениями проверять `git status` каждого затронутого репозитория. Сохранять пользовательские правки и индекс, не делать массовый staging.
- Для разрешённого коммита выбирать только пути задачи. Многострочное сообщение передавать только через Bash heredoc: `git commit -F - <<'EOF'` … `EOF`. Проверять заголовок: `git log -1 --format=%s`.
- Перед работой прочитать README и `.ai/memory/MEMORY.md`, затем документы затронутой подсистемы. Перед изменениями в другом репозитории читать его AGENTS.md.
- Постоянные правила обновлять в AGENTS.md, проверенные сквозные факты — в `.ai/memory/`, решения по фичам — в профильной документации. Не вести отдельные копии знаний для разных агентов.
- CLAUDE.md, GEMINI.md, инструкции Copilot и Cursor — только точки входа в общий контекст.
- Локальные разрешения, MCP, доступы и пути тулчейнов не копировать между агентами автоматически. Наличие доступа не является поручением на публикацию или развёртывание.
- Запускать проверки по характеру изменений. Отдельно указывать проверку сборкой/тестами и проверку на железе. Для изменений только инструкций достаточно проверки ссылок, согласованности и diff.

## Нативная прошивка

- Прочитать [SETUP.md](SETUP.md), [общие инструкции nanoFramework](.ai/upstream-instructions.md) и [рабочий процесс LEDTREES](.ai/memory/project-ledtrees-workflow.md). Этот файл задаёт правила форка; upstream-справка описывает остальные платформы.
- Использовать ESP-IDF v5.5.5, preset `ESP32_LEDTREES_V2` из CMakePresets.json и настроенное локальное окружение. Не менять SDK и плату без соответствующей задачи.
- Конфигурация: `cmake --preset ESP32_LEDTREES_V2`; сборка настроенного дерева: `cmake --build build`. Нужно окружение ESP-IDF из SETUP.md. Собирать вне исходного дерева.
- Перед сменой preset или очисткой учитывать существующие build, sdkconfig и пользовательские настройки. Для текущего target не удалять их без необходимости.
- Interop менять согласованно с ledtrees-esp32/nanoframework/src/interoplib: checksum и mangled-имена должны совпадать. Генерируемые стабы не править вручную; процедура переноса и сохранения ручного кода — в памяти рабочего процесса.
- API компонентов менять согласованно с ledtrees-idf-components. CLR-адаптеры остаются здесь; публичный API компонентов не зависит от nanoFramework.
- Данные устройства должны переживать обновление. Правила миграции и совместимости — в ledtrees-esp32/AGENTS.md и документации форматов.
- MAIN и bundle должны происходить из одного прогона; MAIN получает bundle через `-DeployBundle`. Не прошивать и не публиковать релиз без поручения на это.
- Самостоятельного универсального unit-test runner здесь нет. Проверять нативную сборку; host-тесты компонентов находятся в ledtrees-idf-components/test/host. Runtime и тайминги подтверждать аппаратными проверками и логами.
